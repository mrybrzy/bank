# Bank API

REST API for bank account handling. An account can hold separate balances in `EUR`, `USD`, `SEK`, and `GBP`.

## Setup

Create a local `.env` file. It contains the database username and password used by both PostgreSQL and the Spring Boot application.

```powershell
Copy-Item .env.example .env
```

Example `.env`:

```properties
DB_USERNAME=postgres
DB_PASSWORD=postgres
```

Start the whole application with Docker Compose:

```powershell
docker compose up --build -d
```

The API is available at:

```text
http://localhost:8080
```

To stop the application:

```powershell
docker compose down
```

## Run Tests

This project is made with Java 21.

Run all tests:

```powershell
.\mvnw.cmd test
```
Works only if JAVA_HOME is set to Java 21. Otherwise, you can also run tests in an IDE.


## Request Examples

The demo creates an account, reads the generated account number, and then runs credit, debit, balance, and exchange requests.

`ACC-12345678` in the examples below is only an example of a generated account number. Use the account number returned by the create account request.

### Create Account

`POST /accounts`

Creates a new account for the given username. The response contains the generated account number.

Request body:

```json
{
  "username": "alice"
}
```

Response body:

```json
{
  "accountNumber": "ACC-12345678",
  "username": "alice"
}
```

### Add Money

`POST /accounts/{accountNumber}/credit`

Adds money to one currency balance. Requires `X-Username` for ownership check and a unique `referenceId` for idempotency.

Header:

```text
X-Username: alice
```

Request body:

```json
{
  "amount": 100.00,
  "currency": "EUR",
  "referenceId": "11111111-1111-1111-1111-111111111111"
}
```

Response: `204 No Content`

### Debit Money

`POST /accounts/{accountNumber}/debit`

Debits money from one currency balance. The debit does not use other currencies and does not exchange money automatically. External logging is called before debiting and does not depend on debit operation success. In case logging fails, the debit operation is not attempted.

Header:

```text
X-Username: alice
```

Request body:

```json
{
  "amount": 25.00,
  "currency": "EUR",
  "referenceId": "22222222-2222-2222-2222-222222222222"
}
```

Response: `204 No Content`

### Get All Balances

`GET /accounts/{accountNumber}/balance`

Returns all balances for the account. Requires `X-Username` for ownership check.

Header:

```text
X-Username: alice
```

Response body:

```json
{
  "EUR": 65.00,
  "USD": 10.80
}
```

### Get Balance By Currency

`GET /accounts/{accountNumber}/balance?currency={currency}`

Returns the balance for one currency.

Header:

```text
X-Username: alice
```

Response body:

```json
{
  "EUR": 65.00
}
```

### Exchange Currency

`POST /accounts/{accountNumber}/exchange`

Exchanges money from one currency balance to another using fixed rates. The operation creates one debit ledger entry and one credit ledger entry.

Header:

```text
X-Username: alice
```

Request body:

```json
{
  "amount": 10.00,
  "fromCurrency": "EUR",
  "toCurrency": "USD",
  "referenceId": "33333333-3333-3333-3333-333333333333"
}
```

Response: `204 No Content`

## Logic

Account numbers are generated by the application in the format `ACC-XXXXXXXX`, where the last part is a random uppercase value.

The `X-Username` header is used for account ownership checks. If the username in the header does not match the account owner, the API returns `403 Forbidden`.

Money operations are idempotent by `referenceId`. Each credit, debit, and exchange request must use a unique UUID-like `referenceId`. If the same `referenceId` is sent again, the API returns `409 Conflict` and does not apply the operation twice.

Balances are stored separately per currency. A debit uses only the requested currency, so the API does not automatically exchange money to cover insufficient funds.

Currency exchange uses fixed rates in the application. The exchange creates a debit entry in the source currency and a credit entry in the target currency.

Before a debit request returns success, the controller calls an external logging service after the account service debit call succeeds. If the debit fails, external logging is not called.

Database changes are saved through JPA repositories. Debit and exchange operations lock the account row with a pessimistic write lock to reduce concurrency issues when multiple requests modify the same account.
